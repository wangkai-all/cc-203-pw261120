# 枪口可用性分析

把充电站的三类原始记录 —— **枪口状态消息、充电订单、维修记录** —— 还原成每个枪口逐分钟的
「可服务 / 占用 / 故障 / 离线 / 未确认」时间段，并同时给出两种利用率口径。还原过程可追溯、可比较、
可导出，重算结果以不可变版本保存。

- 纯本地运行，无第三方运行时依赖：Node.js 内置 `node:http`、`node:sqlite`、`node:test`。
- 前端为原生 ES Module 单页应用，手写 SVG 图表，无框架、无构建步骤。
- 样例数据完全虚构。

---

## 快速开始

```bash
npm start          # http://127.0.0.1:4173 ，首次启动自动导入样例并生成初始版本
npm run dev        # 同上，文件变更自动重启
npm test           # 33 个测试（引擎 22 + API 11）
npm run seed       # 仅导入尚不存在的站点
npm run seed:reset # 清空数据库并按样例重建
npm run samples    # 重新生成 data/samples/*.json（确定性，无随机数）
```

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `4173` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `DB_PATH` | `data/app.db` | SQLite 文件路径 |

要求 Node.js ≥ 22.5（`node:sqlite`）。数据库文件已加入 `.gitignore`，删掉即可从头再来。

| 冲突与未确认 | `#/<siteId>/conflicts` | 维修/故障/离线与充电的重叠冲突、未确认区间清单、数据质量问题附录 |
| 迟到消息 | `#/<siteId>/inbox` | 待入箱迟到消息；每条都附「若补入会怎样」的指标增量与时段变化预览，确认后才生成新版本 |
| 版本与对比 | `#/<siteId>/versions` | 版本历史（窗口、时间、原因、输入指纹）；同窗口上一版本与当前版本的逐项差异 |
| 原始记录 | `#/<siteId>/records` | 所有状态/订单/维修原始行，标注分析去向（采用、重复抑制、同时刻未采用、推断结束、无法匹配、无效…），可按枪口/类型/关键词筛选；默认显示全部枪口，只有 URL 带 `gun=` 时才按枪口预筛 |

顶部可切换站点、窗口（1 / 3 / 7 天）、版本，并随时「重算并生成版本」或导出 CSV / JSON。
URL 参数 `days`、`version`、`gun` 都可直接分享；选中的版本自身已确定窗口，因此带 `version` 时不再带 `days`。

## 口径与还原规则

### 1. 状态流

- 状态消息是状态流：一条消息从其**事件时刻**生效，直到下一条消息。最多向后延续 **6 小时**；
  更长的空档视为状态流中断，记 **未确认**，不会沿用旧状态、更不会当作空闲。
- **去重**：同一 `externalId` 或完全相同内容（同状态 + 同事件时刻）只取首条（按到达顺序）。
  同 `externalId` 但载荷不同也会抑制，并在数据质量里单独列出。
- **同时刻冲突**：同一事件时刻出现不同状态时，取**到达时间最晚**的一条（到达时间相同再按来源优先级：
  站端日志 > 充电桩固件 > 第三方网关），并记为「同时刻冲突」，落选记录在原始记录页标注。
- **迟到**：按事件时间看是乱序到达，或到达比事件晚 2 小时以上，标为迟到；消息仍然参与还原，
  不会丢弃。

### 2. 订单与缺失的结束时间

订单是占用证据。结束时间缺失时，**只允许由独立证据界定**：

1. 同一枪口的下一条订单开始；
2. 一条离开「占用」的状态消息；
3. 维修工单开始。

都没有，则从订单开始到窗口结束整段记 **未确认**（`openOrders`），并计入数据质量问题清单。
推断出的结束时间会标注依据（记录 ID），时间线中用虚线/「结束推断」标记。

### 3. 维修、故障、离线与冲突

- 故障集合 = 状态流报故障 ∪ 维修工单窗口（并集，重叠只扣一次）。
- 分类优先级：**故障 > 离线 > 占用 > 未确认 > 可服务**。
- 维修/故障/离线与充电订单重叠时：
  - 记一条冲突（`maintenance_overlap_charging` / `fault_overlap_charging` / `offline_overlap_charging`）；
  - 该时段按**不可用**计一次，既不重复扣减，也不计入有效充电时长。
- 未结束的维修（`endTime` 为空）按窗口结束截断，枪口列表标「维修中」。

### 4. 两种利用率

| 口径 | 公式 | 含义 |
| --- | --- | --- |
| 自然时间口径 | 占用 ÷ **窗口自然时长** | 故障、离线、未确认都在分母里 |
| 可服务时间口径 | 占用 ÷ **可服务时长** | 可服务时长 = 自然时长 − 故障 − 离线 − 未确认 |

`未确认` 永远不会进入「可服务」时长；两个口径差距本身就说明不可用/不可确认时间的占比。
按日统计时，日边界按站点时区的本地零点切分，跨日订单会拆到两天。

### 5. 枪口改名

别名带有效期，按**记录的事件时刻**匹配：改名前的消息用旧名解析；改名后误用旧名也能回溯到同一枪口，
但会标注「过期别名」。原始记录页与明细抽屉都会标出「别名匹配」。

## API

所有接口返回 JSON（导出接口除外）；错误为 `{ "error": "..." }` 加对应状态码。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 + 引擎版本 |
| GET | `/api/sites` | 站点列表（含枪口/记录数与待入箱数） |
| GET | `/api/sites/:id` | 站点详情、枪口、别名、默认窗口 |
| GET | `/api/sites/:id/analysis?days=3` 或 `?start=…&end=…` 或 `?version=…` | 完整分析结果；无版本时取该窗口最新版本，不存在则按需生成（`reason: auto`） |
| GET | `/api/sites/:id/timeline` / `/guns/:gunId/timeline` | 时间线数据 |
| GET | `/api/sites/:id/versions` | 版本历史 |
| POST | `/api/sites/:id/recompute` | `{ start, end, reason?, note? }`；输入指纹未变则返回 `unchanged: true`，不新建版本 |
| GET | `/api/sites/:id/inbox?version=…` | 迟到消息 + 每条「补入后」的内存预览（不落库） |
| POST | `/api/sites/:id/inbox/:itemId/ingest` | `{ start, end }` 显式补入，生成 `late_message` 版本；重复补入返回 409 |
| GET | `/api/sites/:id/records` | 全部原始记录与别名 |
| GET | `/api/sites/:id/export?version=…&format=csv\|json` | 明细导出 |
| POST | `/api/dev/reset-samples` | 按样例重建（会清空该站点全部版本） |

窗口限制：`days` 为 1–31；`start/end` 跨度不超过 62 天；结束必须晚于开始。

### 版本

每次重算、迟到补入都会生成新版本，保存窗口、生成时间、引擎版本、**输入指纹**（原始记录 + 窗口的哈希）
和完整结果。同一窗口同一指纹不会重复生成。旧版本永久保留，可通过 `?version=` 切回，并与上一版本逐项对比。

### 导出

- **CSV**（UTF-8 带 BOM，Excel 直接打开）：每行一个时段，`kind` 区分 `segment`（时间线区间）、
  `unconfirmed`（未确认区间）、`conflict`（冲突）、`day` / `gun-day`（按日汇总）；
  同时给出 ISO 时间与站点本地时间，附证据记录 ID、冲突 ID、推断结束标记与原因。
- **JSON**：版本元数据、全站与按枪口指标、按日指标、区间、冲突、数据质量，以及逐枪口原始记录。

文件名带站点、版本号与本地日期，例如 `availability-site-xingqiao-v1-2026-11-13-2026-11-15.csv`。

## 已知边界

- 状态消息只有「状态 + 事件时刻」两类信息；两份来源互相矛盾且到达时间相同时，只能按来源优先级裁决，
  冲突会如实列出供人工复核。
- 事件时刻向下取整到分钟，区间细分与统计都按分钟粒度（不足一分钟的区间会被合并到相邻区间）。
- 迟到消息补入是**显式**操作：预览只读内存，不修改数据，也不会自动重算。
- 单枪时间线的最小绘制宽度为 620px；窄屏（≤760px）下改为横向滚动而不是整体缩小，以保证刻度与图例可读。
  表格在窄屏内横向滚动，页面本身不会出现横向溢出。
